# 03. Технический стек, ввод с пера и оценка рукописного письма (print + cursive)

**Статус:** исследование / архитектурное предложение, версия 1.1 (2026-10-13)
**Целевое железо:** XPPen Artist 12 Pro (второй монитор 1920×1080, 11,6"), Windows 10 22H2 и Windows 11
**Аудитория продукта (уточнено заказчиком):** дети **8–10 лет**. Учим два стиля: печатный (print) и **английское слитное письмо (cursive)**. **Конечная цель — беглое слитное письмо;** печатный трек вспомогательный.
**Интерфейс:** переключаемый RU/EN.

Условные обозначения:
- **[проверено]** — подтверждено официальной документацией или первоисточником (ссылка рядом);
- **[вторичный источник]** — обзор, форум, сторонний сайт;
- **[не проверено]** — моё предположение или вывод по аналогии, нужно проверить спайком.

## 0. Главное коротко

1. **Стек:** **.NET 10 (LTS, поддержка до ноября 2028) + WPF**. Логика оценки живёт в отдельной библиотеке на чистом .NET, без зависимостей от UI, и покрыта детерминированными тестами. Запасной вариант — **Avalonia 11/12**: тот же C#, ядро переиспользуется на 100%. План C — Electron с Web Pointer Events. .NET 8 не подходит: его поддержка заканчивается 10.11.2026.
2. **Ввод с пера.** Ставим на Windows Ink (галочка «Windows Ink» в драйвере XPPen включена). У нас есть абстракция `IPenInputSource` с двумя реализациями:
   (а) WPF `StylusPlugIn` (RealTimeStylus, перо обрабатывается в отдельном потоке);
   (б) собственный обработчик `WM_POINTER` через `HwndSource` и `GetPointerPenInfoHistory`. Он отдаёт coalesced-точки с метками времени QPC для каждой точки, что важно для кинематики беглости.
   Какую реализацию оставить, решим по результатам аппаратного спайка. Wintab — только запасной путь (WintabDN, MIT).
3. **Оценщик слитного письма — ядро продукта.** Задача — **принудительное выравнивание (forced alignment)**, а не распознавание: мы знаем, какое слово должен написать ребёнок. Эталон слова собирается из моделей букв cursive (тело + входящий/выходящий штрих) и процедурных соединений по классам (baseline/diagonal, high/horizontal, break). Рукопись сопоставляется с конкатенированным эталоном через DTW по признакам «позиция в координатах линейки + направление касательной», с якорями на ключевых точках. Для вариантов букв используется DP по графу эталонов (level-building / one-pass DP). Отложенные штрихи (точки над i/j, перекладины t/f, второй штрих x) сначала отделяются, затем назначаются своим буквам. Каждая буква и каждое соединение получает оценку отдельно: форма, направление, линейки, размер, наклон, качество соединения. Отдельно считаются метрики беглости: скорость, отрывы пера, паузы, NIV.
4. **ML не нужна** для MVP. Геометрия + DTW + правила дают объяснимый фидбэк («соединение ушло от линии», «петля l ниже линии асцендеров»), а это и есть педагогическая ценность. Позже, когда соберём оценки экспертов, можно обучить веса итогового балла лёгкой регрессией.
5. **Эталоны** — свой JSON-формат: координаты в единицах x-height (baseline = 0, x-height = 1). Поддерживаются несколько «скриптов» (print, precursive, cursive), стили (UK joined, US cursive), варианты букв, классы входа/выхода, отложенные компоненты, стрелки и номера. Источники для авторинга: Playwrite (OFL, школьные шрифты с joined-вариантами; это контуры, а не центральные линии), Relief SingleLine (OFL, однолинейный, только print), Hershey (пермиссивная лицензия с атрибуцией). Формат KanjiVG взят как образец идеи.
6. **Аудио** — заранее сгенерированные и записанные ассеты (OGG/WAV). На наличие английских голосов Windows на русской системе не рассчитываем. Фонемы записывает человек. TTS (Piper/Kokoro) используем только на этапе сборки, лицензии голосов проверяем по MODEL_CARD.
7. **Первый спайк** — два параллельных трека:
   (S1) железо: частота, давление, координаты при смешанном DPI, press-and-hold, hot-plug, задержка;
   (S2) алгоритм cursive: выравнивание 10–20 слов, точность сегментации на буквы, обработка отложенных штрихов на реальных записях взрослых, потом детей.

Что это значит для продукта:
- 200 Гц дают точку каждые ~5 мс. При скорости письма ребёнка 30–80 мм/с шаг между точками 0,15–0,4 мм. Для оценки формы этого с запасом хватает. Для кинематики (NIV, скорость) нужны **точные метки времени каждой точки** (см. §2.4).
- Наклон нам почти не нужен. Можно собирать его для аналитики хвата пера, но в MVP — нет.
- Давление используем для ширины линии на экране и, возможно, для метрики «слишком сильный нажим». Через Windows Ink давление нормировано в 0..1024 ([POINTER_PEN_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-pointer_pen_info) [проверено]), то есть фактически 1024 уровня. Для нашей задачи это неважно.
- Пикселей на миллиметр: 1920 / 256 мм ≈ **7,5 px/мм**, примерно 190 PPI. Windows почти наверняка предложит для этого монитора масштаб 150%, а основной монитор часто стоит на 100%. **Получается смешанный DPI**, и отсюда требование Per-Monitor V2 (§7.4).
- Нет touch — хорошо: ладонь на экране не даёт ложных касаний. Но **кнопки и диск** драйвер превращает в сочетания клавиш, и ребёнок может нажать их случайно (§2.3).

### 1.2. Драйвер на Windows: Windows Ink и Wintab

- В приложении драйвера XPPen (вкладка **Pen settings**) есть галочка **Windows Ink** ([XPPen FAQ](https://www.xp-pen.com/faq/troubleshooting-no-pressure-sensitivity-in-krita) [проверено]).
  - **Включена:** драйвер отдаёт перо через стек Windows Ink. Приложения на `WM_POINTER`, WISP/RealTimeStylus (WPF), Chromium/Edge/WebView2, UWP/WinUI видят устройство как **перо** с давлением.
  - **Выключена:** система получает от пера только эмуляцию мыши, давление доступно лишь через **Wintab** (`wintab32.dll`, его ставит драйвер XPPen). Так работает режим WinTab в Krita/CSP (FAQ XPPen выше; [обсуждение Krita](https://krita-artists.org/t/difference-between-wintab-and-windows-ink-input/12781) [вторичный источник]).
- Известная проблема: в части программ с Windows Ink нет правого клика, без него нет давления ([тред Capture One/Xencelabs](https://support.captureone.com/hc/es/community/posts/4409815893009-Issues-with-no-Pen-Pressure-with-Windows-Ink-checked-in-the-Xencelabs-Pen-Tablet-Driver-How-do-I-fix-it) [вторичный источник]). Нам правый клик не нужен.
- **Маппинг на монитор.** В драйвере есть раздел Work Area/Monitor: в режиме «Расширить» выбирается монитор, на который отображается перо, есть кнопка Identify ([руководства XPPen, напр. Artist 12 2nd](https://www.xp-pen.com/user-manual/artist-12-2nd) [проверено для родственных моделей]; для 12 Pro — [не проверено], но UI драйвера общий). Типичная проблема — после смены основного монитора или переподключения перо уезжает на другой экран. Лечится в драйвере. Программно мы можем это **обнаружить**: `POINTER_DEVICE_INFO.monitor` — «HMONITOR дисплея, на который отображено устройство» ([learn.microsoft.com](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-pointer_device_info) [проверено]). Если монитор пера не совпадает с монитором окна, показываем родителю подсказку.
- **Задержка.** Официальных цифр нет. Складывается из частоты отчётов (5 мс), драйвера, стека Windows Ink, рендера приложения и кадра монитора (14 мс отклика матрицы по спецификации). Ожидаю 30–70 мс «от пера до пикселя» [не проверено]. Меряем в спайке (камера 240 fps).
- Обзор parkablogs: параллакса нет благодаря ламинации, джиттера на диагоналях нет; Windows Ink приходится переключать под конкретные программы ([parkablogs](https://www.parkablogs.com/index.php/content/review-xp-pen-artist-12-pro-pen-display-vs-artist-133-pro) [вторичный источник]).

**Вывод.** Требуем от пользователя Windows Ink = ON и проверяем это при первом запуске на экране диагностики пера: тип указателя = Pen, давление меняется, частота около 200 Гц. Если приходят только мышиные события без давления, показываем пошаговую инструкцию со скриншотами драйвера.

## 2. Ввод с пера в Windows: помехи и как их убрать

### 2.1. Стеки ввода

| Стек | Что даёт | Кто использует |
|---|---|---|
| `WM_POINTER*` (Win8+) | `POINTER_PEN_INFO`: давление 0..1024, tiltX/Y ±90°, поворот, флаги (барабанная кнопка, ластик), **история coalesced-точек** (`GetPointerPenInfoHistory`), `PerformanceCount` (QPC) и `dwTime` для каждой точки | Chromium, Qt ≥ 5.12, Godot (winink), Avalonia [не проверено, по API похоже], свой Win32-код |
| WISP / RealTimeStylus (Tablet PC) | пакеты пера в отдельном потоке, низкая задержка динамического рендера | **WPF по умолчанию**, WinForms Ink |
| Wintab | давление и наклон напрямую от драйвера, мимо Windows Ink | Krita/Photoshop (режим WinTab), WintabDN |

[GetPointerPenInfoHistory](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getpointerpeninfohistory) [проверено] возвращает все точки, склеенные в текущее сообщение, в обратном хронологическом порядке. Историю нужно забрать до следующего `GetMessage`, иначе она теряется.

### 2.2. Системные помехи Windows Ink и их отключение

| Помеха | Что делать в приложении (программно, только для своего окна) | Что может сделать родитель в настройках |
|---|---|---|
| **Press-and-hold → правый клик** (кольцо, которое растёт под пером) | WPF: `Stylus.IsPressAndHoldEnabled="False"` на окне или холсте ([Stylus class](https://msdn.microsoft.com/en-us/vstudio/ms611755(vs.110)) [проверено]). Win32: на `WM_TABLET_QUERYSYSTEMGESTURESTATUS` вернуть `TABLET_DISABLE_PRESSANDHOLD` (0x1) или выставить свойство окна `MicrosoftTabletPenServiceProperty` ([WM_TABLET_QUERYSYSTEMGESTURESTATUS](https://learn.microsoft.com/en-ie/Windows/Win32/tablet/wm-tablet-querysystemgesturestatus-message) [проверено]) | «Перо и Windows Ink» / «Перо и сенсорный ввод» → снять «Нажатие и удержание для правого клика». Реестр `HKCU\Software\Microsoft\Wisp\Pen\SysEventParameters\HoldMode` ([elevenforum](https://www.elevenforum.com/t/enable-or-disable-pen-press-and-hold-for-right-clicking-in-windows-11.6349) [вторичный источник]) — **программно не трогаем**, это системная настройка |
| **Визуальный фидбэк** (круги и рябь при касании, двойном касании, barrel) | `SetWindowFeedbackSetting(hwnd, FEEDBACK_PEN_TAP/DOUBLETAP/PRESSANDHOLD/RIGHTTAP/BARRELVISUALIZATION, …, FALSE)`: значения 2–6 в [FEEDBACK_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ne-winuser-feedback_type) [проверено], Win8+. WPF: `Stylus.IsTapFeedbackEnabled="False"` | «Перо и Windows Ink» → «Показывать визуальные эффекты» = выкл. |
| **Flicks** (жесты-«щелчки») | WPF: `Stylus.IsFlicksEnabled="False"`; Win32: `TABLET_DISABLE_FLICKS` в ответе на тот же запрос | В Win10 флики в UI, судя по всему, уже не настраиваются [не проверено] — отключаем на всякий случай |
| **Курсор под пером** | `Cursor = None` на холсте, свой маркер кончика пера при hover | «Показывать курсор» |
| **Панель рукописного ввода / Ink Workspace** | в детском режиме нет текстовых полей; PIN вводится экранными кнопками | «Писать в текстовых полях пером» (Win11) |
| **Barrel-кнопка пера** (по умолчанию правый клик) | игнорируем события с барабанной кнопкой и ластиком при оценке; штрих с зажатой кнопкой считаем ошибочным касанием | в драйвере XPPen назначить кнопке «нет действия» |
| **Express keys / диск** → клавиатурные сочетания | в киоск-режиме перехватываем клавиши в окне. Если на кнопке висит Win-сочетание, нужен low-level hook (§7.3) | в драйвере XPPen отключить кнопки или назначить безвредные действия (инструкция в мастере настройки) |

Принцип: **в системных настройках сами ничего не меняем.** Отключаем помехи только для своего окна (это поддерживаемые per-window API), а всё глобальное объясняем родителю в мастере первичной настройки.

### 2.3. Как надёжно получать давление и точки

Порядок предпочтения:
1. **WM_POINTER (Windows Ink)** — основной путь. Если `pointerType == PT_PEN`, берём `GetPointerPenInfoHistory`: все точки и время QPC каждой.
2. **WPF Stylus (WISP)** — `StylusPoint.PressureFactor` (0..1); tilt через `StylusPointProperties.XTiltOrientation/YTiltOrientation`, если устройство их объявило. **Минус:** у `StylusPoint` нет метки времени для каждой точки. Есть только `StylusEventArgs.Timestamp` на пачку, поэтому время внутри пачки придётся интерполировать при номинальных 200 Гц.
3. **Wintab** (WintabDN, [MIT, NuGet WacomSolutionPartner.WintabDotNet](https://packages.nuget.org/packages/WacomSolutionPartner.WintabDotNet) [вторичный источник, лицензия по SourceForge]) — запасной путь, если на конкретной машине Windows Ink ведёт себя плохо.

Признак проблемы: событие пришло как мышь (`PT_MOUSE` / `StylusDevice == null`) при подключённом XPPen. Значит, Windows Ink выключен — показываем диагностику.

### 2.4. Почему важны метки времени каждой точки

Беглость слитного письма — продуктовая цель, а её метрики (скорость, NIV — number of inversions in velocity, паузы) считаются по производным от времени. По исследованиям, NIV снижается с практикой: «движения автоматизируются к 8 годам, автоматизм обычно достигается около 10 лет» ([Gerth et al., PMC10769097](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC10769097/); [PMC8172624](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC8172624/) [проверено]). Это ровно наш возраст 8–10, так что метрики беглости — не украшение. Нужны время QPC для каждой точки (WM_POINTER даёт его) или как минимум аккуратная интерполяция.

## 4. Оценка рукописи по эталону

### 4.1. Что значит «оценить», а не «распознать»

Классификатор отвечает на вопрос «какая это буква». Нам нужно другое: **насколько хорошо написана заданная буква или слово и что именно исправить.** Это:
- **сопоставление (alignment)** рукописи с известным эталоном;
- **набор объяснимых метрик** по частям: штрих, буква, соединение;
- **правила педагогики:** что считать ошибкой на текущем уровне, какой допуск, о чём сказать в первую очередь.

### 4.2. Нормализация: координаты линейки, а не bounding box

Классический $-family масштабирует фигуру к единичному bounding box и центрирует. Положение и размер при этом теряются, а для письма это **ошибка проектирования**: «p», поднятая над baseline, и «l» ниже линии асцендеров — это ошибки, которые надо видеть.

Принятая система:
- y вверх, **baseline = 0, x-height (линия средней строки) = 1.0**. Линия асцендеров/прописных — например, 1.7, десцендеров — −0.7; конкретные значения — параметр стиля.
- x в тех же единицах. Начало — точка старта эталона слова на строке.
- Перевод «экранные px → линейка»: `u = (x_px − x0) / h_px`, `v = (y_baseline_px − y_px) / h_px`, где `h_px` — x-height линейки в физических px. На экране размер линейки задаём **в миллиметрах**: 7,5 px/мм на этом мониторе.
- Ориентиры размера для 8–10 лет (педагогическая гипотеза, **[не проверено]**, уточнить с методистом): обучение — x-height 12–15 мм; беглое письмо — 6–8 мм, ближе к тетради.
- Сдвиг по x допускаем: ребёнок может начать слово чуть правее. Сдвиг по y **не нормализуем**, а измеряем как ошибку посадки на baseline.
- Масштаб: оценщик делает **два прохода**. Первый — грубая оценка масштаба ребёнка (медиана высот x-height-сегментов) для устойчивого выравнивания. Второй — оценка в абсолютных единицах линейки, где «слишком крупно/мелко» становится метрикой, а не нормализуется.

### 4.4. Конвейер оценки печатной буквы (print) — второстепенный трек

1. Предобработка: отбрасываем hover-точки и штрихи с barrel-кнопкой; удаляем дубликаты; убираем выбросы (скачок > N·медиана); **ресэмплинг по длине дуги** с шагом 0,03–0,05 x-height. Сглаживание только для отображения, в оценку идут сырые данные плюс лёгкий фильтр (Savitzky–Golay или 1€-фильтр).
2. Сопоставление штрихов: матрица стоимостей DTW «штрих ребёнка × штрих эталона» (каждый также против обращённого эталона), затем Венгерский алгоритм → получаем назначение, порядок и направление.
3. Метрики по штриху: среднее и максимум DTW-отклонения (единицы x-height), дискретный Фреше, доля точек в коридоре τ, покрытие эталона, ошибка старта (расстояние до стартовой точки), направление (forward vs reversed cost, монотонность параметра дуги вдоль DTW-пути), ошибки по линейкам (верх и низ относительно x-height/asc/desc), пропорции, наклон.
4. Метрики по букве: Stroke Count Error, Stroke Ordering Error (по GREAT), размер, посадка на baseline.
5. Фидбэк: 1–2 главные проблемы по таблице приоритетов (сначала направление и старт, потом форма, потом линейки, потом размер).

### 4.5. ЯДРО: оценщик слитного письма (cursive)

#### 4.5.1. Особенности cursive, которые ломают «побуквенные» подходы

- Слово пишется **одним или несколькими длинными штрихами**. Границы букв внутри штриха не видны.
- **Соединения (joins)** — отдельные элементы с собственной формой и правилами. В британской школьной методике 4 типа: diagonal к букве без асцендера, diagonal к букве с асцендером, horizontal без асцендера, horizontal с асцендером. Horizontal выходят из **o, r, v, w** («top exit»). Есть **break letters**, которые не соединяются: в разных схемах это b, g, j, p, q, s, x, y ([Twinkl Y2](https://www.twinkl.com/guides/year-2-english-subject-support/year-2-handwriting-and-letter-formation), [школьные документы UK](https://morley.cambs.sch.uk/wp-content/uploads/2020/11/Y4_Joining_letter_sets.pdf) [вторичный источник, но согласуется между школами]).
- В США распространены петлевые Zaner-Bloser и D'Nealian (100% соединений). Около 90% детей, идущих по пути print → cursive, учат один из них. Getty-Dubay Italic не петлевой, соединяет не всё; D'Nealian имеет наклон 17° ([Wikipedia: Getty-Dubay Italic](https://en.wikipedia.org/wiki/Getty-Dubay_Italic), [Zaner-Bloser](https://en.wikipedia.org/wiki/Zaner-Bloser_(teaching_script)) [вторичный источник]). **Стиль — параметр продукта.** Начать с одного (решить с методистом) и заложить «пакеты стилей».
- **Отложенные штрихи (delayed strokes):** точки i/j, перекладины t (и f в некоторых стилях), второй штрих x, иногда перекладина у заглавных. Обычно их ставят после слова, но часть учителей учит ставить сразу. В литературе по онлайн-распознаванию их обычно выделяют эвристикой и удаляют или переносят ([KIT/NPen++](https://isl.iar.kit.edu/english/4761.php); сравнительное исследование — [Sabancı](https://research.sabanciuniv.edu/37074/) [вторичный источник]).
- **Ретрейс:** в a, d, g, q, а также h, m, n, p, r перо идёт обратно по уже написанной линии. Это не ошибка, и эталон должен его содержать.
- Дети 8–10 лет пишут вариативно: колебания наклона, «гуляющая» baseline, лишние отрывы, остановки, дорисовки и подправки.

#### 4.5.2. Модель эталона cursive

Каждая буква в стиле `cursive/<style>` описывается так:
- **тело (body)** — один или несколько штрихов с порядком и направлением; ретрейс-участки отмечены;
- **точка и класс входа (entry):** `baseline` (вход снизу диагональю), `xheight` (вход сверху горизонтально), `ascender-tall` (b, h, k, l, f, t: диагональ, уходящая к асцендеру или к высоте t), `c-shape` (a, c, d, g, o, q, s: соединение «перекатывается» к верхней правой точке старта и начинается против часовой);
- **точка и класс выхода (exit):** `baseline` (большинство), `high` (o, r, v, w — на уровне x-height), `none` (break letters), `descender-loop` (g, j, y, z в петлевых стилях);
- **lead-in / lead-out** — входящий и выходящий штрих для **изолированной** буквы в упражнениях. В слове первый lead-in заменяется входом, а между буквами стоит join;
- **отложенные компоненты** (`deferred`): тип (dot, bar, cross), якорь относительно тела (например, «над стволом i на высоте 1.4±0.2»), направление (t-bar слева направо), политика времени (`afterWord` | `immediate` | `either`);
- **варианты** (`variant`): например, `r` после high-exit, `e` с высоким входом после o/v/w, `s` в двух формах, `f` петлевая или нет, `k` с петлёй или без. Выбор варианта — по контекстным правилам стиля.

**Соединения генерируются процедурно, по правилам классов.** Это один из ключевых архитектурных выводов:
- таблица правил стиля: `(exitClass, entryClass) → joinShape`, плюс исключения для пар (например, `o→e`, `w→o`) и break-правила;
- форма join — кубический Безье (Hermite) от точки выхода к точке входа с заданными касательными: непрерывность касательной (G1) с телом слева и справа плюс параметры «прогиба» (horizontal join — провис не ниже 0,85·x-height, [гипотеза]);
- длина join (межбуквенный интервал) задаётся стилем, ширина буквы — advance;
- так из 26 + 26 букв и десятка правил получаются **все** слова без ручной отрисовки каждой пары. Ручные исключения — только где автоматика выглядит плохо.

Источники для авторинга cursive-форм:
- **Playwrite** (TypeTogether, Google Fonts, **OFL**). Школьные шрифты 40 стран, в том числе **Playwrite GB J (England Joined)**, **GB S (SemiJoined)**, **US Trad** (петлевой cursive), **US Modern**; к каждому есть версия «Guides» с линейками ([TypeTogether](https://www.type-together.com/playwrite-instructions), [Google Fonts GB J](https://fonts.google.com/specimen/Playwrite%2BGB%2BJ/about) [проверено: OFL по Fontsource/Google Fonts]). **Это контурные шрифты (залитые формы), а не центральные линии и не порядок штрихов.** Используем их как визуальный референс и подложку для авторинга. Центральную линию можно получить скелетизацией глифа (полуавтоматически), но порядок, направление и ретрейсы размечает человек.
- **Hershey script** (scripts/scriptc): однолинейные, но каллиграфия XIX века, не школьный стиль. Лицензия разрешает любое использование с атрибуцией Dr. A. V. Hershey / NBS и запрещает только NTIS-формат ([Fedora: Hershey Font License](https://fedoraproject.org/wiki/Licensing/HersheyFontLicense) [проверено]). Подходит разве что для тестов.
- **Relief SingleLine** (OFL; SVG, OTF-SVG, TTF, UFO; есть строчные и прописные) — только **печатный** однолинейный, хорошая стартовая точка для print-трека ([GitHub isdat-type/Relief-SingleLine](https://github.com/isdat-type/Relief-SingleLine) [проверено]).

#### 4.5.3. Алгоритм: принудительное выравнивание слова

Вход: целевое слово `w = c1…cn`, стиль S, рукопись — список штрихов со временем.
Выход: сегментация рукописи на буквы, соединения и отложенные штрихи; оценки по каждой части; фидбэк.

**Шаг 0. Построение эталона слова (`WordTemplateBuilder`).**
Выбираем варианты букв по контекстным правилам и расставляем буквы по advance. Генерируем join-сегменты или отмечаем break (ожидаемый отрыв). Получаем:
- `mainPath` — последовательность сегментов с метками `(letterIndex, part ∈ {entry, body, join, exit})` и ожидаемыми отрывами пера;
- `deferred[]` — отложенные компоненты с привязкой к букве;
- `keypoints[]` — ключевые точки эталона: старт буквы, пики (верх петли l, верх h), касания baseline, точки возврата (cusps) у ретрейса, вершины горбов m/n/u.

Шаг ресэмплинга — 0,04 x-height. Для каждой точки храним `(u, v, θ)`: позиция и направление касательной; кривизну — опционально.

**Шаг 1. Отделение отложенных штрихов.**
Эвристика-кандидат: штрих начинается **левее** конца предыдущего штриха больше чем на ~0,5 x-height (возврат назад по x) **и** короткий (длина < 0,6 x-height) **или** точечный (bbox < 0,15). Последние по времени короткие штрихи — сильные кандидаты.
Если политика `either`, короткий штрих посреди слова над i или t тоже допустим: финальное решение принимается на шаге 4 по геометрии, эвристика лишь предлагает кандидатов.

**Шаг 2. Склейка основного следа.**
Основные штрихи соединяются в одну последовательность в хронологическом порядке. Между ними вставляется маркер «перо поднято» с виртуальным прыжком: признак `penUp = 1`, без интерполяционных точек.
Ожидаемые отрывы эталона (break letters) — такие же маркеры. Стоимость DTW:
- совпали «отрыв ↔ отрыв» — 0;
- отрыв там, где эталон ожидает join, — штраф «лишний отрыв». Это **не ошибка формы, а метрика беглости**; при этом положение join всё равно оценивается.

**Шаг 3. Выравнивание (`CursiveAligner`).**
- Базовый вариант (MVP, стиль без вариантов внутри слова): **DTW между рукописью и конкатенированным эталоном**.
  - Локальная стоимость: `c(i,j) = wp·‖p_i − q_j‖² + wθ·(1 − cos(θ_i − θ_j)) + wpen·[penUp_i ≠ penUp_j]`.
  - Позиция берётся после грубой нормализации масштаба (проход 1, §4.2) и сдвига по x (по первой точке или open-begin DTW).
  - Ограничения: Sakoe-Chiba band по **нормализованному прогрессу**: `|i/N − j/M| ≤ 0,15–0,25`, потому что ребёнок может сильно растянуть одну букву. Ограничения наклона пути — не более 2–3 шагов подряд по одной оси.
  - Компонента направления делает выравнивание **чувствительным к направлению**: обратный ход даёт высокую стоимость, и это ловится как ошибка направления.
- **Якоря** (anchors): ключевые точки рукописи — минимумы скорости, экстремумы по y, точки максимальной кривизны (cusps). Это классические точки сегментации онлайн-письма. Совпадение ключевой точки рукописи с ключевой точкой эталона того же типа даёт бонус к стоимости (мягкий якорь). Это стабилизирует границы в «гребёнках» вроде *minimum* (m, i, n, u подряд), где чистый DTW может «съехать» на горб.
- **Варианты и альтернативы** (следующий этап): у буквы K вариантов, join зависит от соседних вариантов → **one-pass DP по графу эталонов** (как в слитной речи у Ney / level building у Myers–Rabiner). Состояние = (вариант буквы k в позиции t, индекс точки внутри варианта). Переходы — по допустимым join. Сложность O(N·ΣM_k), для слова это доли миллисекунды.
  Можно добавить альтернативы «ребёнок оторвал перо и начал букву заново» и «пропущенная буква» с высоким штрафом. Это даёт осмысленный фидбэк «пропущена буква r» вместо «всё плохо».
- **Инкрементальный режим** (по ходу письма): **open-end DTW** префикса рукописи против эталона слова. Каждые ~50 мс узнаём, на какой букве ребёнок сейчас, и ловим грубые ошибки — неверный старт, явно обратное направление — для мягкой подсказки сразу. Полная оценка — по завершении слова: пауза > 1,0–1,5 с после отрыва или кнопка «Готово».

**Шаг 4. Назначение отложенных штрихов.**
По результату шага 3 известны области букв i, j, t, x, f в рукописи. Для каждого `deferred`-слота считаем стоимость кандидатов: позиция относительно реального ствола ребёнка (а не эталона!), форма (точка или отрезок), направление (t-bar слева направо), длина. Назначаем Венгерским алгоритмом.
- Не назначенный слот → «забыл поставить точку над i» / «нет перекладины t».
- Лишний штрих → «лишняя черта».
- Нарушение временной политики (поставил точку, не дописав слово, при `afterWord`) → мягкое замечание, только если методист включил строгий режим.

**Шаг 5. Оценка частей.**
Для каждой буквы — на её сегменте рукописи против её тела эталона, с локальным повторным выравниванием:
- форма: средний и максимальный DTW, Фреше, доля в коридоре;
- направление и старт;
- линейки: x-height-буквы достигают 1,0±τ; асцендеры ≥ 1,5; десцендеры ≤ −0,5; касание baseline;
- **закрытость** овалов a, d, g, o, q (зазор < 0,1);
- **петли:** l, b, h, k, f — петля есть или её нет, в зависимости от стиля; e — петля не схлопнута;
- ретрейс: ствол d или a прописан обратно, а не петлёй (если стиль требует);
- наклон: угол квазивертикальных участков; важна **консистентность** внутри слова больше, чем абсолютное значение;
- пропорции: ширина относительно эталона.

Для каждого соединения:
- есть ли (нет отрыва);
- правильная высота: horizontal join держится около x-height, diagonal идёт от baseline;
- гладкость (нет угла или петли, где их не должно быть);
- вход в следующую букву в правильной точке: для c-shape — «перекатился» к старту, а не врезался в середину овала.

Для слова:
- консистентность x-height (коэффициент вариации высот);
- консистентность наклона;
- посадка на baseline (тренд и разброс);
- интервалы;
- отложенные штрихи;
- **беглость:** общее время, средняя скорость в x-height/с, число отрывов vs ожидаемое, паузы > 200 мс внутри слова, **NIV на букву** (инверсии скорости; меньше — лучше), доля времени в воздухе.

**Шаг 6. Агрегирование и педагогический фидбэк.**
- Каждая метрика переводится в «оценку 0..1» кусочно-линейной функцией с порогами **по уровню сложности**: коридор сужается по мере прогресса.
- Итог уровня буквы и слова — взвешенная сумма. Плюс **пороговые «стоп-ошибки»**, которые нельзя компенсировать: неверное направление, пропущенная буква.
- Фидбэк: максимум 1–2 главных замечания и 1 похвала. Визуально — подсветка проблемного сегмента (буквы или соединения) на «призраке» эталона, повтор анимации только этой буквы или join.
- Все пороги и веса лежат в **конфигурации** (JSON), а не в коде. Методист тюнит их без программиста; тесты фиксируют поведение.

#### 4.5.4. Педагогическая прогрессия (важно для оценщика)

Лестница для 8–10 лет, итог — беглое cursive:
1. Печатные буквы — проверка навыка; у многих детей уже есть.
2. **Precursive:** печатные буквы с lead-out «хвостиками». Тот же формат, `script = precursive`.
3. Изолированные cursive-буквы с lead-in и lead-out по семействам движений: c-family (c, a, d, g, o, q), горбы (n, m, h, k, b, p), петли (l, e, f), «короткие» (i, u, t, j, y), r, s, v, w, x, z.
4. **Пары с одним типом соединения:** diagonal → x-height (in, an, un), diagonal → ascender (al, ut, il), horizontal (on, ov, wi, re), horizontal → ascender (ol, wh).
5. Тройки и частые слова, слова с отложенными штрихами.
6. Слова на время: беглость, NIV, отрывы. Короткие фразы.
7. Заглавные cursive и их соединения (часть заглавных не соединяется — правило стиля).

Оценщик знает уровень, поэтому включает или отключает метрики. Например, беглость не штрафуется до шага 6.

#### 4.5.5. Открытые реализации и опубликованные подходы для cursive

- **Открытого готового оценщика детского слитного письма нет** (поиск не нашёл). Ближайший опубликованный — IntuiScript/IRISA: эластичный letter spotting, нечёткие модели формы, направления и порядка; без исходного кода. Их же открытый **Children Handwritings Database**: 27 000 символов, 24 cursive-буквы, 147 детей 3–7 лет, свободно для исследований с цитированием ([IRISA](https://www-intuidoc.irisa.fr/en/children-handwritings-database/) [проверено]). Подходит для калибровки, но это французский cursive и маленькие дети.
- Общие техники: level-building/one-pass DTW (слитная речь), open-end DTW, эвристики delayed strokes (NPen++), сегментация по минимумам скорости и экстремумам y.
- Метрики: GREAT (Vatavu et al. 2013), кинематика беглости (NIV, отрывы, паузы — [PMC10769097](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC10769097/)).
- Коммерческие аналоги для ориентира: School Rebound (EPFL), Dynamilis (5–12 лет) — используют ML ([EPFL](https://actu.epfl.ch/news/using-ai-to-help-children-get-ahead-in-handwriting) [вторичный источник]).
- Датасеты взрослых: IAM-OnDB — только некоммерческие исследования, с регистрацией ([FKI](https://fki.tic.heia-fr.ch/databases/iam-on-line-handwriting-database) [проверено]); UNIPEN — исторический. **Для продукта лицензионно непригодны**; для внутренних экспериментов — по условиям лицензии.

#### 4.5.6. Нужна ли ML?

**Для MVP — нет.**
1. Задача — выравнивание с известным эталоном. DTW/DP решает её оптимально по заданной стоимости, без обучения.
2. Нужен **объяснимый** фидбэк по частям (буква, соединение, линейка). У нейросети-классификатора его нет без дополнительной инженерии.
3. Детских размеченных данных по английскому cursive у нас нет. Сбор и разметка — месяцы работы.
4. Детерминированность и тестируемость (golden tests) — требование заказчика.
5. Вычислительно всё укладывается в миллисекунды на CPU.

**Где ML может пригодиться позже:**
- обучение **весов** итогового балла по оценкам экспертов (логистическая или порядковая регрессия на наших интерпретируемых признаках);
- классификатор «что вместо этого написал ребёнок» ($P/$Q как лёгкий вариант);
- калибровка порогов по возрасту.

Всё это — небольшие модели поверх признаков, без deep learning в рантайме.

#### 4.5.7. Риски оценщика cursive и как их снять

| # | Риск | Последствие | Как снять |
|---|---|---|---|
| C1 | Неоднозначная сегментация в «гребёнках» (m/n/u/i/w подряд), путаница e/l (высота петли) | неверная буква подсвечивается как ошибочная | якоря по ключевым точкам; проверка числа горбов; тестовый набор «трудных слов» (minimum, umm, nine, will, letter); метрика точности границ на размеченных данных |
| C2 | Ребёнок учил в школе другой стиль (US vs UK, петли или без) | ложные «ошибки» | пакеты стилей, выбор стиля родителем; варианты букв; «мягкий» режим, где принимаем допустимые альтернативы |
| C3 | Отложенные штрихи поставлены сразу, в другом порядке или далеко | ложные пропуски | политика `either`; назначение по геометрии относительно реального ствола; синтетические тесты на все порядки |
| C4 | Подправки, повторные обводки, остановки | DTW «залипает»; искажённая форма | детект «дорисовки» (участок, повторно проходящий уже написанное > N мм) как отдельной ошибки беглости; допуск в DTW (горизонтальные шаги); пауза ≠ ошибка формы |
| C5 | Слишком строгая оценка демотивирует (а мотивация 8–10 лет критична) | отказ от продукта | консервативные стартовые пороги; калибровка на реальных данных; согласованность с оценками 2–3 экспертов (цель — Cohen's κ ≥ 0,6 [ориентир]); адаптивные пороги; «режим учителя» с визуализацией решений оценщика |

### 5.2. Рекомендуемый формат глифа (JSON)

Принципы:
1. Координаты — в **единицах линейки** (baseline = 0, x-height = 1, y вверх).
2. Штрихи — кубические Безье (точно и компактно для авторинга). Перед использованием они ресэмплируются в полилинии.
3. Порядок и направление явные: порядок массива и направление пути.
4. Один файл — один глиф (символ × скрипт × стиль × вариант). Удобно для диффа и ревью ИИ.
5. Версия схемы и JSON Schema для валидации в CI.

### 5.3. Инструменты авторинга (dev-tools, не для ребёнка)

- **GlyphEditor** — небольшое WPF-окно или веб-страница. Подложка (Playwrite-глиф на линейке), рисование пером по подложке → автоматический фит Безье. Ручная правка контрольных точек, порядка, направления, ретрейсов, ключевых точек, классов входа и выхода. Предпросмотр анимации и всех join с соседями.
- **GlyphValidator** (запускается в CI):
  - JSON Schema;
  - G1-непрерывность на стыках;
  - точки входа и выхода лежат на теле;
  - буква не выходит за линии больше допуска;
  - ресэмплированный эталон, оценённый самим собой, даёт 1.0;
  - все 26×26 пар собираются без самопересечений join.
- **Golden-рендер:** PNG-листы всех букв и пар для ревью человеком; diff картинок в PR.

## 7. Хранение, упаковка, полноэкранный режим, DPI, локализация

### 7.1. Хранение прогресса

- **SQLite** (`Microsoft.Data.Sqlite`, MIT; SQLitePCLRaw, Apache-2.0) в `%LocalAppData%\PenForLang\data.db`, WAL. Устойчив к сбоям, транзакции, легко делать миграции. JSON-файлы проще, но хуже переносят частые записи и прерывания (ребёнок выдернул питание).
- Схема (набросок):
  - `profiles(id, name, avatar, birth_year, ui_lang, style_id, created)`;
  - `item_state(profile_id, item_id, mode, box/stability, due_at, last_score, streak, lapses)` — интервальное повторение;
  - `attempts(id, profile_id, item_id, mode, started_at, duration_ms, score_json, feedback_codes, ink_blob)` — `ink_blob` хранит сжатые сырые точки для повтора и пересчёта новой версией оценщика;
  - `sessions`, `settings`, `schema_version`.
- **Интервальное повторение:** для детей достаточно модифицированного Leitner (5–6 коробок) с переходом по порогу оценки и «освоенностью» по нескольким успешным попыткам подряд. FSRS — избыточен для MVP [мнение].
- **Экспорт:** ZIP (JSON профиля и попыток + CSV-сводка для родителя), импорт для переноса на другой ПК. Опционально экспорт штрихов в **InkML** (W3C) для внешнего анализа.
- PIN родителя хранится как PBKDF2-хеш с солью. Все данные локальные, без сети.

### 7.3. Полноэкранный режим на мониторе пера и блокировка выхода

1. **Определение монитора пера:** при старте `GetPointerDevices()` → среди устройств с типом pen берём `monitor` (HMONITOR, на который отображено перо) ([POINTER_DEVICE_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-pointer_device_info) [проверено]). Запасной вариант — монитор с разрешением 1920×1080 и физическим размером около 256×144 мм (EDID через `EnumDisplayDevices`/WMI) [не проверено]. Последний выбор родителя запоминаем.
2. Окно: borderless (`WindowStyle=None`, `ResizeMode=NoResize`, `Topmost=True`). Позиционирование **в физических пикселях** через `SetWindowPos` после `SourceInitialized`: при смешанном DPI WPF-координаты в DIP вводят в заблуждение.
3. Реакция на `WM_DISPLAYCHANGE`, `WM_DPICHANGED`, `WM_POINTERDEVICECHANGE` и пропажу устройства: пауза и экран «Подключи планшет».
4. Родительский экран — на основном мониторе (отдельное окно) или на том же по PIN.
5. **Блокировка выхода:**
   - отмена `Closing` без PIN; перехват Alt+F4;
   - скрытый жест для родителя: долгое нажатие в углу + PIN на экранной клавиатуре;
   - Win-клавишу и Alt+Tab можно глушить low-level keyboard hook (`WH_KEYBOARD_LL`) только пока активен детский режим и окно в фокусе. Ctrl+Alt+Del заблокировать нельзя, и это правильно.
   - Полный киоск — Windows Assigned Access (отдельная учётная запись; доступность в редакции Home — [не проверено]). Документируем как опцию для родителя, сами не настраиваем.
6. Express keys XPPen: в мастере первичной настройки — инструкция отключить их в драйвере.

### 7.4. DPI awareness

- В `app.manifest`: `<dpiAwareness>PerMonitorV2</dpiAwareness>` (+ `<dpiAware>true/pm</dpiAware>` для совместимости).
- WPF сам масштабирует UI по мониторам. Для **своего WM_POINTER-обработчика** координаты приходят в физических экранных пикселях: `ScreenToClient` → деление на DPI-масштаб окна (`VisualTreeHelper.GetDpi`).
- Известны проблемы смещения стилуса и тач-индикаторов при разных DPI мониторов в сторонних WPF-компонентах ([Telerik feedback](https://feedback.telerik.com/wpf/1682141-touchmanager-wrong-tap-and-hold-touch-indicator-position-in-a-setup-with-multiple-monitors-with-different-dpi-scale-settings-and-enabled-dpi-awareness-of-the-wpf-application) [вторичный источник]); у GTK есть похожий баг. **Пункт спайка:** точность в углах экрана при масштабах 100/125/150% на обоих мониторах.
- Размеры линейки задаём в **мм**, пересчитываем через физический DPI монитора, а не через логический масштаб Windows. Делаем калибровку «приложи линейку» у родителя.

### 7.5. Локализация RU/EN

- Интерфейс и инструкции — `.resx` (`Strings.ru.resx`, `Strings.en.resx`) + markup extension с динамическим переключением языка без перезапуска.
- Контент (буквы, слова, аудио английской речи) от языка UI не зависит. Аудио инструкций — отдельные наборы RU и EN.
- Коды фидбэка (`JOIN_TOO_LOW`, `WRONG_DIRECTION`, `MISSING_DOT_I` …) переводятся в текст и озвучку через таблицу локализации. **Оценщик выдаёт только коды и параметры**, без строк, поэтому тесты не зависят от языка.
- Тест в CI: все ключи присутствуют в обоих языках.

## 8. Тестирование без планшета

### 8.1. Формат записи траекторий (pen log)

JSON Lines (`.pfl.jsonl`, при хранении gzip). Первая строка — заголовок, далее события:

```jsonc
{"type":"header","schema":"pfl.penlog/1","app":"1.4.0","os":"10.0.19045","device":{"product":"XPPen Artist 12 Pro","source":"wm_pointer","rateHz":200},
 "screen":{"wPx":1920,"hPx":1080,"mmW":256,"mmH":144,"dpiScale":1.5},
 "guides":{"x0Px":180,"baselinePx":620,"xHeightPx":105,"style":"uk-joined-v1"},
 "task":{"itemId":"word:rain","script":"cursive","mode":"copy","level":4},"qpcFreq":10000000}
{"type":"p","t":0,"x":231.4,"y":598.2,"p":0.31,"tx":12,"ty":-8,"btn":0,"ph":"down"}
{"type":"p","t":50123,"x":232.0,"y":597.1,"p":0.35,"tx":12,"ty":-8,"btn":0,"ph":"move"}
{"type":"p","t":1203300,"x":410.7,"y":612.9,"p":0.0,"btn":0,"ph":"up"}
{"type":"ev","t":1500000,"name":"done-button"}
```

- `t` — микросекунды от начала (из QPC); `x, y` — физические px клиентской области; `p` — 0..1; `tx, ty` — наклон в градусах; `ph` — down/move/up/hover.
- Конвертер в InkML и обратно — для обмена и внешних инструментов.
- **Режим записи** в продукте: включается родителем, с согласием, данные локальные. Плюс dev-режим с разметкой.
- **ReplaySource** реализует `IPenInputSource` и воспроизводит лог с виртуальными часами в реальном или ускоренном времени. На нём строятся интеграционные тесты UI и отладка.

### 8.2. Синтетические «детские» штрихи

Генератор (`tools/SynthInk`, используется и в юнит-тестах) с **фиксированным seed** — детерминированный:
1. Берёт эталон буквы или слова (из `WordTemplateBuilder`).
2. Кинематика: профиль скорости по сегментам (минимум рывка или sigma-lognormal по Plamondon) и сэмплинг 200 Гц с джиттером ±0,3 мс.
3. Деформации:
   - глобальные: масштаб 0,7–1,4, наклон ±15°, поворот ±4°, дрейф baseline;
   - локальные: гладкий шум (Perlin или гауссов процесс, σ 0,02–0,08 x-height, корреляционная длина 0,2–0,5);
   - тремор 8–12 Гц малой амплитуды;
   - перелёты и недолёты на поворотах;
   - паузы 100–600 мс;
   - лишние отрывы в join.
4. **Мутации с метками ошибок** (ground truth): обратное направление штриха или буквы; неверная точка старта; пропущенное соединение; лишняя или отсутствующая петля (l↔i, e схлопнута); буква выше или ниже линий; нет десцендера; перепутан порядок; точка или перекладина пропущена, смещена, поставлена сразу или после; пропущенная или вставленная буква; замена буквы (a→o, n→u); ретрейс заменён петлёй; дорисовка поверх.
5. Тесты проверяют, что оценщик **находит ровно внесённую ошибку** (класс плюс локализация: буква или соединение). В CI считается матрица ошибок по классам с порогами: например, recall по направлению ≥ 0,98, по пропуску точки ≥ 0,97, ложные срабатывания на «чистых» шумных образцах ≤ 3% [целевые цифры, уточнить].

### 8.3. Виды тестов

- **Юнит** (xUnit): ресэмплинг, DTW (против эталонной наивной реализации), Фреше, коридор, нормализация в линейку, построение эталонов, join-генератор, назначение delayed strokes.
- **Property-based** (FsCheck, BSD-3): инварианты.
  - Эталон, оценённый сам собой, даёт 1.0.
  - Сдвиг по x не меняет оценку формы.
  - Сдвиг по y меняет метрику baseline, но не форму.
  - Обращение любого штриха даёт ошибку направления.
  - Увеличение шума монотонно снижает оценку (статистически).
  - Оценщик детерминирован: одинаковый вход — побитово одинаковый выход.
- **Golden / snapshot** (Verify, MIT): набор реальных записей (взрослые, затем дети) → JSON разбора (сегментация, метрики, коды) с округлением до 3 знаков. Изменение оценщика видно в диффе PR. Принятие нового снимка — осознанное ревью.
- **Визуальные golden:** PNG-рендеры глифов, пар join, оверлеев «эталон vs рукопись» для ревью.
- **UI-интеграция:** ReplaySource плюс FlaUI (MIT) или тесты ViewModel без окон. Большая часть логики в ViewModel и сервисах тестируется без UI.
- **Производительность** (BenchmarkDotNet): выравнивание слова из 8 букв — меньше 5 мс на слабом ноутбуке [цель].
- **Аппаратный чек-лист** (ручной, перед релизом): Win10 22H2 и Win11; Windows Ink вкл/выкл; масштабы 100/125/150%; смена основного монитора; hot-plug; сон и пробуждение; барабанная кнопка; express keys.

### 9.4. Спайки: что проверить в первую очередь

Делаем **параллельно** два трека в первые 1–2 недели.

**S2 — алгоритм cursive (приоритет №1, ядро; можно начать без железа).**
1. Вручную авторить 1 стиль: буквы `a c d e i l n o r t u w` + join-правила (baseline, high, c-shape) + отложенные (i, t).
2. Реализовать `WordTemplateBuilder` + `CursiveAligner` (DTW по конкатенированному эталону + якоря) + `DeferredStrokeAssigner`.
3. Тестовый набор из 15–20 слов, включая трудные: *an, in, on, it, tin, net, ten, rain, tide, note, cat, dot, wet, low, road, little, minimum, letter, window, tired*.
4. Данные:
   - (а) синтетика с мутациями;
   - (б) 3–5 взрослых × 20 слов × 3 повтора на XPPen, мышью — только для отладки;
   - (в) как только будет можно — 3–5 детей 8–10 лет.
5. Разметить границы букв и соединений в InkLab.
6. **Критерии успеха:**
   - граница буквы найдена с ошибкой < 0,2 x-height в ≥ 90% случаев на взрослых и ≥ 80% на детях;
   - назначение отложенных штрихов ≥ 97%;
   - детекция внесённых ошибок направления ≥ 95%;
   - ложные «ошибки» на аккуратных образцах ≤ 5%;
   - время оценки слова < 10 мс.
7. **Решение по итогам:** достаточно ли DTW + якорей, или сразу нужен one-pass DP с вариантами; какие признаки нужны (кривизна, скорость).

**S1 — аппаратный спайк (на реальном XPPen Artist 12 Pro, Win10 22H2 и Win11).** Тестовое WPF-приложение с тремя источниками (WPF Stylus, свой WM_POINTER hook, Wintab), выводит живые графики.
1. Тип указателя, давление (диапазон, монотонность), наклон, **реальная частота** (ожидаем ~200 Гц), джиттер меток времени, наличие coalesced-истории.
2. Как всё меняется при Windows Ink вкл/выкл в драйвере.
3. Точность координат в 9 точках экрана при масштабах 100/125/150% на каждом мониторе (PerMonitorV2), при смене основного монитора.
4. Отключение press-and-hold, кругов фидбэка, flicks через per-window API. Поведение barrel-кнопки.
5. **Hot-plug USB и HDMI** при работающем приложении (проверка зависания WISP); сон и пробуждение.
6. Приходят ли `WM_POINTER` в `HwndSource`-hook при `DisableStylusAndTouchSupport=true`.
7. Задержка «перо → пиксель» (камера 240 fps): DynamicRenderer vs свой слой.
8. Определение монитора пера через `GetPointerDevices().monitor`, полноэкранное окно на нём, корректность после `WM_DISPLAYCHANGE`.
9. Что шлют express keys и диск по умолчанию, перехватываются ли они в окне.

**S3 — контент-пайплайн (мини, 2–3 дня):** формат JSON → валидатор → анимация начертания со стрелками и номерами → рендер всех пар join в PNG. Цель — проверить, что процедурные соединения выглядят приемлемо.

**S4 — аудио (мини):** сгенерировать 26 названий букв и 50 слов (Piper ljspeech / alba / Kokoro), слепое сравнение качества; записать 5 фонем человеком; проверить задержку воспроизведения NAudio vs MediaPlayer.
