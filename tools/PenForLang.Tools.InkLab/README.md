# InkLab — запись, повтор и разметка (V0.9)

Инструмент разработчика (WPF, `tools/PenForLang.Tools.InkLab`, в установку не входит). Одно окно, четыре вкладки:
**Запись**, **Повтор**, **Разметка**, **Сводка**. Вкладки «Зонд», «Глифы», «Эксперт», «Разбор» из ARCHITECTURE.md §2.2 появятся позже.

## Запуск

| Как | Что получится |
|---|---|
| `6-inklab.cmd` в папке пакета V0 (`build\publish-v0.cmd` кладёт InkLab рядом с программой) | перо через `WM_POINTER`, окно на мониторе пера |
| `6-inklab.cmd --mouse` | мышь как перо (работа без планшета) |
| `dotnet run --project tools/PenForLang.Tools.InkLab -- --mouse` | то же из исходников |

Параметры: `--mouse`, `--corpus-dir <папка>` (корпус; по умолчанию `%LOCALAPPDATA%\PenForLang\corpus`), `--content-dir <папка>`,
`--monitor <N>`, `--xheight-mm <мм>` (по умолчанию 15), `--subject <id>`, `--annotator <id>`, `--exit-after <сек>`.
При сбое интерфейса сообщение показывается в окне, подробности — в `%LOCALAPPDATA%\PenForLang\inklab-crash.log`.

## Как записывать (для взрослых)

1. Откройте вкладку **Запись**. Введите **идентификатор субъекта** (например `adult-1`; имя не нужно), отметьте «левша», если пишете левой.
   Возраст и номер согласия — по желанию (взрослому согласие не нужно). Нажмите **«Начать / продолжить»**.
2. Протокол: буквы `a`, `i`, `t` по 30 раз, затем слово `at` 20 раз (10 «с отрывом пера на соединении», 10 «слитно, перекладина t сразу»).
   Слева на холсте анимируется эталон; **пишите справа, копируя его**, в обычном темпе, аккуратно. Указание к каждой подсказке — над холстом.
3. Кнопки:
   - **Готово** — попытка сохраняется отдельным файлом, показывается следующая подсказка;
   - **Заново** — холст очищается, попытка продолжается (в записи останется только последняя версия); работает, когда перо поднято;
   - **Пропустить** — подсказка помечается пропущенной (к ней можно вернуться из списка слева двойным щелчком);
   - **Назад** — предыдущая подсказка; если записать её заново, прежняя запись уйдёт в подпапку `superseded`;
   - **Показать эталон** — анимация ещё раз.
4. Закрыть окно можно в любой момент: прогресс хранится в `progress.json` папки субъекта, при следующем запуске с тем же идентификатором запись
   продолжится с места остановки.

Записи лежат в `<корпус>\<субъект>\<подсказка>-<дата-время>.pfl.jsonl.gz` (формат `pfl.penlog/1`, ARCHITECTURE.md §3.4; в заголовке:
`task` — что просили написать, `subject` — взрослый без имени, линейка, экран, устройство). Точки наведения не пишутся.

## Повтор

Вкладка **Повтор**: «Папка…» (или «Файл…») → выберите запись → **Играть**. Воспроизведение идёт через `ReplayPenSource` в реальном времени или
ускоренно (0,5×…8×), «Показать всё» рисует попытку целиком. След — поверх линеек в x-height; слева направо — как писали; «Заново» стирает
холст, как у пишущего. Ниже — метаданные записи.

## Как размечать

Вкладка **Разметка**: «Папка…» → выберите запись (в списке видно, размечена ли она). Для каждой записи:

1. **Что написано** — буквы по порядку без пробелов (по умолчанию — цель задания, например `at`). Если написано не то, исправьте и поставьте флаг «написано не то».
2. **Границы букв.** Инструмент «Границы букв», выберите стык (`a|t`) и **кликните по следу там, где кончается левая буква**.
   Для стыка есть два вида (кнопка под стыком):
   - **соединены** — перо не отрывалось: граница ставится в ближайшую точку штриха;
   - **отрыв пера** — граница привязывается к концу штриха левой буквы и началу следующего основного штриха.
   Цвет следа показывает, какой букве принадлежит участок; чёрные метки — границы; серый пунктир — соединительный штрих между концом левой и началом правой буквы.
3. **Отложенные штрихи** (точка `i`, перекладина `t`). Инструмент «Отложенные штрихи», выберите букву, кликните по штриху; повторный клик снимает отметку.
   Кнопка «⇄» переключает «сразу / после слова» (по умолчанию выводится из порядка штрихов). Отложенные штрихи исключаются из основного следа.
4. **Качество**: «годится» или брак (снимите галочку), флаги и заметка.
5. **Сохранить** (запись рядом с логом). Справа — проверка: границы идут по порядку, стыков ровно «букв − 1», точки есть в записи и т. д.
   Неполная разметка сохраняется как черновик (в списке — «начато, ошибок: N»). При переходе к другой записи несохранённое сохраняется автоматически.
   Кнопки ◀ ▶ и «К неразмеченной» — навигация.

### Формат файла разметки `pfl.annotation/1`

Файл `<имя записи>.pfl.jsonl.gz.ann.json` лежит рядом с записью. Номера штрихов и точек — как в `PenLog.ToInkAttempt()` (штрихи после последнего «Заново», с 0).

```json
{
  "schema": "pfl.annotation/1",
  "penlog": "at-lift-001-20261014-120000.pfl.jsonl.gz",
  "target": "word:at",
  "annotator": "A",
  "annotatedAt": "2026-10-14T12:00:00Z",
  "text": "at",
  "quality": { "usable": true, "flags": [], "note": null },
  "strokeSamples": [21, 21, 11],
  "junctions": [
    { "after": 0, "kind": "lifted", "end": { "stroke": 0, "sample": 20 }, "start": { "stroke": 1, "sample": 0 } }
  ],
  "deferred": [
    { "stroke": 2, "letter": 1, "kind": "crossbar", "timing": "afterWord" }
  ]
}
```

- `text` — что фактически написано; букв `n = длина text`.
- `junctions` — стыки между буквами `after` и `after + 1`, ровно `n − 1`. `end` — где кончается тело левой буквы, `start` — где начинается тело правой;
  участок `end…start` — соединительный штрих (при `end = start` его нет). `kind`: `connected` (стык внутри одного штриха) или `lifted`
  (`end` — последняя точка штриха, `start` — первая точка следующего основного штриха).
- `deferred` — отложенные штрихи: `letter` (с 0), `kind` (`dot`, `crossbar`, `other`), `timing` (`immediate` — сразу после ствола, `afterWord` — после слова; по утверждению разметчика).
- `quality.usable` — годится/брак; `flags`: `wrongContent`, `corrected`, `hesitation`, `outOfGuides`, `deviceGlitch`, `other`. Для брака стыки не обязательны.
- `strokeSamples` — число точек в каждом штрихе на момент разметки; если запись изменилась, проверка сообщит `stroke-mismatch`.
- Основной след — все штрихи, кроме отложенных. Тело буквы `k`: от начала стыка `k−1` (для первой — от начала следа) до конца стыка `k` (для последней — до конца следа).
- JSON Schema: `schemas/pfl.annotation.v1.schema.json`; проверка — `AnnotationValidator` (коды замечаний — `IssueCodes`).

## Сводка

Вкладка **Сводка** → «Обновить сводку»: сколько записей по видам (`glyph:a`, `word:at · lift`, `word:at · crossbar`…) и по субъектам, сколько
размечено верно, сколько брака, сколько начато и сколько без разметки. «Сохранить» кладёт `corpus-summary.md` в корень корпуса.

## Для разработчика

- ViewModel (`ViewModels/`), протокол (`Protocol/`), корпус (`Corpus/`), разметка (`Annotation/`), сцена для рисования (`Scene/`) не зависят от окна;
  тесты — `tests/PenForLang.Tools.InkLab.Tests`. Окно (`MainWindow`, `Views/`) только связывает слои и источник пера.
- XAML не ссылается на типы этой же сборки (вкладки создаются в коде): иначе WPF собирает временную сборку, и общий `Directory.Build.props`
  с `AssemblyName = $(MSBuildProjectName)` ломает разметку (`MC3074`).
- Протокол и экранный эталон слова — временные: слово показывается из изолированных глифов; после V0.10 (`WordTemplateBuilder`) эталон заменится настоящим.
